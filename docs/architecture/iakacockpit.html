IakaCockpit

Dépôt : ~/work/IakaCockpit (HEAD 2ed1690, v0.33.0). Chemins relatifs au dépôt.

V / VÉRIFIÉ lu dans le code ou la config S / SUPPOSÉ déduit, non prouvé PRÉVU cadré, non livré

Rôle

  • V Application de bureau placée au-dessus du portefeuille de projets du « chapeau » (~/work) : vue d'ensemble des dépôts, une session de travail par projet, pilotage de l'équipe d'agents ; le terminal reste la source de vérité, le chat n'est qu'une vue filtrée (README.md:3-10).
  • V Frontière avec iakaFrameGUI : la forge fabrique et livre les équipes, le cockpit les réceptionne, les lie et les exécute (README.md:12-13, src-tauri/src/handoff.rs:1-5).

MQTT

  • V Aucun client MQTT dans le cockpit : pas de crate MQTT dans src-tauri/Cargo.toml, aucune occurrence de souscription/publication dans src-tauri/src ni src/. maincourante.rs:5-8 le dit explicitement : « on ne réimplémente NI le bus MQTT, NI le pont n8n/bridge… jamais de souscription temps réel ».
  • V MQTT n'apparaît qu'indirectement, de deux façons :
  • Lecture (aval du bus) : la main courante est lue dans CouchDB, alimentée par iakaboxlogs (agents → Mosquitto → pont → CouchDB) (specs/PROJET.md:250,307,400).
  • Émission (via n8n) : notify_user envoie au webhook n8n une valeur support ∈ {slack, discord, mqtt} (src/api/backend.ts:141 ; src-tauri/src/notify.rs:298 ; choix UI src/views/SettingsView.tsx:68). n8n route ; le nœud n8n-nodes-base.mqtt « MQTT (a completer) » est un placeholder désactivé, topic = body.cible, credential broker iakabox à créer en UI (docker/n8n/canal-adresse.workflow.json:28,74-79 ; docker/n8n/README.md:27,45).
  • V Topics, QoS, retain : non définis côté cockpit ; le topic serait la chaîne opaque cible (src/api/backend.ts:569). QoS/retain dépendraient du nœud n8n, non configuré.
  • S Aucun lien avec le broker local d'iakaOS (iaka/<domaine>/{in,out}) : rien dans le code ne publie sur ces topics.
