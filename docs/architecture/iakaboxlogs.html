Rôle

Main courante centralisée des conversations des agents IA de l'écosystème iakaframe : les agents publient chaque message sur un broker MQTT, un pont le persiste dans CouchDB, et on consulte via Fauxton (et le flux live via MQTTX Web) V CLAUDE.md:20-26, README.md:3-5. Hébergée sur l'iakabox (VM2 192.168.2.11), hors service depuis la panne de l'iakabox du 2026-08-19 ; son successeur (broker VPS mqtt.naonedge.com + CouchDB) est en cadrage [V doc] naonedge-vps/specs/instructions/mqtt-broker-vps.md:14-21, iakaframe/BACKLOG.md:26-27.

Fonctionnement (flux principal)

  • Un agent (skill log-conversation / iakaframe-log-conversation) lance node iakalog.mjs --role … --content … V skills/log-conversation/SKILL.md:23-27.
  • iakalog.mjs construit le topic ${prefix}/${royaume}/${agent}/${conv} et le payload {role, content, ts, tokens, meta[, _id]} V bin/iakalog.mjs:58-61, ouvre une socket TCP brute, envoie CONNECT MQTT 3.1.1 (user/pass, keepalive 30 s, clean session) puis, au CONNACK=0, un PUBLISH QoS 0 non retenu (octet 0x30) et ferme V bin/iakalog.mjs:66-86. Timeout 7 s, sortie code 1 en cas d'échec V bin/iakalog.mjs:25,76,82,85.
  • Le pont (n8n : MQTT Trigger iakaboxlogs/# → Code « Build Doc » → HTTP POST http://couchdb:5984/conversations en Basic auth V n8n/workflow-bridge.json:8,22,31-47 ; ou repli bridge/index.js : subscribe iakaboxlogs/# puis POST ${COUCHDB_URL}/${COUCHDB_DB} V bridge/index.js:20,45-49) découpe le topic en royaume/agent/conv_id, parse le JSON (sinon content = payload brut) et crée un document V bridge/index.js:28-42.
  • Consultation : Fauxton http://192.168.2.11:5984/_utils, base conversations, index Mango idx-maincourante sur ts, royaume, agent, conv_id V scripts/init-couchdb.sh:17-23 ; flux live via MQTTX Web (8090, WS 9883) [V doc] CLAUDE.md:45-51.

Le workflow n8n est livré "active": false avec des credentials à remplacer (REPLACE_MQTT_CRED, REPLACE_COUCHDB_CRED) V n8n/workflow-bridge.json:3,17,47 ; lequel des deux ponts tournait réellement en prod : S n8n selon CLAUDE.md:110 (« bout-en-bout validé »).

Ergonomie

Aucune UI propre : on consomme des UIs tierces V.

  • Fauxton (:5984/_utils) : zones clés pour annotation — liste des bases (→ conversations), vue « All Documents » (un doc par message), éditeur JSON d'un doc (champs royaume, agent, conv_id, role, content, meta.canal), onglet « Run A Query with Mango » (index idx-maincourante) [S, UI standard CouchDB].
  • MQTTX Web (:8090) : panneau connexions (host 192.168.2.11, port WS 9883, user/pass), zone abonnement iakaboxlogs/#, fil des messages avec topic + payload JSON [S, UI standard MQTTX].
  • Page projet générée par docgen : doc/index.html [V existence].
  • Captures : impossibles actuellement (iakabox hors service) [V doc].

Points ouverts

  • _id ignoré par les ponts : iakalog.mjs:14 et delegation-guard.mjs:250 affirment que « le bridge l'honore », mais bridge/index.js:33-42 et le « Build Doc » n8n ne recopient pas _id → pas d'idempotence via le broker (seul le transport docdb l'a, 409). V
  • Variables incohérentes : iakalog.mjs lit IAKALOG_MQTT_URL et préfixe déf. iakaboxlogs ; les hooks lisent IAKALOG_BROKER_URL et préfixe déf. logs (delegation-guard.mjs:257,262) → sans IAKALOG_PREFIX=iakaboxlogs, les hooks publient hors du iakaboxlogs/# du pont. V
  • SKILL.md demande cd bin && npm install (skills/log-conversation/SKILL.md:14) alors que le publisher est zéro dépendance ; README « À venir » liste encore la skill de push déjà livrée (README.md:102). V
  • Schémas cibles divergents pour le successeur : iakaboxlogs/<royaume>/<agent>/<conv> vs iakaframe/<projet>/<agent>/<evenement> QoS 1 + retain (iakaframe/BACKLOG.md:20-21) vs iakaframe/_logs (VPS). [V doc]
  • Pas de TLS, QoS 0 fire-and-forget (perte silencieuse si le pont est down, sauf persistance Mosquitto non applicable au QoS 0) ; rétention 1 an et dashboards Grafana non faits (CLAUDE.md:112-113). V
  • Adresse 192.168.2.11 codée en défaut ; la mémoire projet iakaos signale l'iakabox en 192.168.1.139 — de toute façon hors service depuis le 19/08. [V doc]
