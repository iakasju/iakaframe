Rôle

  • V C'est la « forge » de la méthode iakaframe, une appli de bureau pour le build-time : on y compose méthodes, rôles, personas, skills, gardes-fous, workflows et équipes, puis on les déploie sous forme de kits (README.md:3-10).
  • V Frontière avec IakaCockpit : la forge fabrique et livre, le cockpit sélectionne, lie et exécute. Runner et modèle restent côté Cockpit (specs/PROJET.md:18, :46 AR-1).

Stack et composants

  • V Coquille Tauri 2 : front React 18 + TypeScript + Vite, backend Rust mince (package.json:31-39, src-tauri/Cargo.toml:21).
  • V Un seul processus applicatif (fenêtre main, 1180x800) (src-tauri/tauri.conf.json:12-20). Il n'y a pas de sidecar : src-tauri/binaries/ est un emplacement réservé et vide, sans externalBin (src-tauri/binaries/README.md).
  • V Port 3030 en dev seulement (Vite, strictPort). Le commentaire note que le Cockpit occupe 3020 (vite.config.ts:4-11, tauri.conf.json:9). En production, aucun port n'est ouvert en écoute S : l'appli sert dist/ et le code ne montre aucun serveur.
  • V Monorepo npm à workspaces. Le paquet @iakaframe/core (packages/core) est le cœur des concepts, en TS pur : types, parseurs et générateurs de kits (packages/core/package.json:4, packages/core/src/adapters/*).
  • V Modules Rust : teams_store, library_store, settings, project_conf, llm, kit_deploy, handoff, pathguard, paths (src-tauri/src/lib.rs:31-39).
  • V Plugins Tauri : dialog, shell, updater, process (src-tauri/src/lib.rs:51-65).
  • V CSP stricte : connect-src 'self' ipc: http://ipc.localhost (tauri.conf.json:24). Tout le réseau passe donc par Rust.

Fonctionnement (flux principal)

  • V App monte ForgeShell (src/App.tsx:8-12). La barre du haut porte 9 onglets : frame · méthode · team · persona · éléments · assemblage · models · kit · apprentissage (src/forge/ForgeShell.tsx:83-93).
  • V Lecture et écriture de la bibliothèque iakaframe (IAKAFRAME_HOME, commune avec le CLI). Ordre de résolution : override settings.json, puis env IAKAFRAME_HOME, puis auto-détection de ~/work/iakaframe à condition d'y trouver library/ et methods/ (src-tauri/src/paths.rs:101-144).
  • V Édition d'un document (New/Open/Save via DocBar), en mode édition ou création (ForgeShell.tsx:336-355).
  • V Génération pure d'un kit Claude Code dans @iakaframe/core, qui produit .claude/skills/<id>/SKILL.md, CLAUDE.md, .claude/settings.json, .claude/hooks/*.mjs et .mcp.json en option (packages/core/src/adapters/claudeCode.ts:235-257). L'écriture disque se fait par kit_deploy, non destructive par défaut et protégée par pathguard (src-tauri/src/kit_deploy.rs:1-17).

Schéma de flux

MQTT

  • V L'application ne se connecte pas à MQTT. Aucun client MQTT n'existe dans src/ ni dans src-tauri/src/, et Cargo.toml ne déclare aucune dépendance MQTT.
  • V Le seul MQTT se trouve dans le hook distribué dans les kits delegation-guard.mjs (global/hooks/delegation-guard.mjs, recopié dans guardScripts.generated.ts:30-31). Ce script tourne dans la session Claude Code du projet cible, pas dans la GUI :
  • broker : IAKALOG_MQTT_URL, par défaut mqtt://192.168.2.11:1883, une ancienne adresse iakabox (:262) ;
  • topic publié : ${IAKALOG_PREFIX||"iakaboxlogs"}/<royaume>/<agent>/<conv> (:268) ;
  • publication QoS 0 sans retain : en-tête 0x30 (:279). Pas de souscription ;
  • message JSON {_id, role:"system", content:"Delegation X -> Y : …", ts, tokens:0, meta:{canal:"geste", event:"delegation"|"delegation_refused", from, to, verdict?, refused?}, royaume, agent, conv_id} ;
  • émission seulement si IAKALOG_USER et IAKALOG_PASS sont définis, timeout 1500 ms, fail-open (:45, :195-196). Le repli IAKALOG_TRANSPORT=couchdb fait un POST CouchDB.
  • V Dans les kits générés par la GUI, le garde n'est branché que sur PreToolUse / Task (packages/core/src/guardrail.ts:165). S Dans ce cas, seul le chemin « délégation refusée » émet sur MQTT. L'émission au RETOUR, prévue en PostToolUse, n'est pas branchée.

Points ouverts

  • Le kit ne branche pas PostToolUse pour delegation-guard : l'émission MQTT des délégations réussies est-elle perdue ? S, à confirmer avec le CLI iakaframe (guardrail.ts:165).
  • Le hook des kits cible par défaut l'IP obsolète 192.168.2.11:1883, alors que la mémoire projet donne l'iakabox en 192.168.1.139 (delegation-guard.mjs:262).
  • PROJET.md:90 annonce « SQLite + keychain », mais le code lit et écrit la clé API en clair dans settings.json (settings.rs:104-110). La doc et le code divergent.
  • La clé de frame active (frame) est marquée « nom à confirmer au dépôt canon » (project_conf.rs:22-23).
  • Le sidecar CLI (P3) n'est jamais branché : le pilotage se fait par le PATH ou par node.
