Rôle

Mosquitto 2.1 tourne dans le socle Docker du VPS NaonEdge. C'est le « bus d'événements iakaframe », joignable depuis Internet, chiffré et authentifié (VÉRIFIÉ, stack/mosquitto/mosquitto.conf:1, stack/compose.yml:222-226). Il est le successeur du broker local de l'iakabox (~/work/iakaboxlogs), qui n'était joignable que sur le LAN et qui est en panne depuis le 2026-08-19. Il ne le relaie pas : aucun pont entre les deux brokers (VÉRIFIÉ, specs/instructions/mqtt-broker-vps.md:13-21, ponts inter-brokers écartés :555).

Fonctionnement (flux principal)

  • Un publisher (agent sur le Mac, le PC Windows ou le VPS) ouvre mqtts://mqtt.naonedge.com:8883 avec le compte iakaframe-publisher. Mosquitto termine lui-même le TLS (VÉRIFIÉ, specs/instructions/mqtt-broker-vps.md:112-116).
  • Il publie sous iakaframe/#, seul espace qu'autorise l'ACL (VÉRIFIÉ, stack/mosquitto/acl:2-3).
  • Les abonnés lisent : un navigateur passe par wss://mqtt.naonedge.com (Caddy → naonedge-vps-mqtt:9001, compte dashboard), un futur pont passe par naonedge-vps-mqtt:1883 sur naonedge-proxy (compte bridge) (VÉRIFIÉ, stack/Caddyfile:84-91, acl:5-10).
  • Le certificat se renouvelle ainsi : Caddy renouvelle, puis mqtt-certs.sh compare les empreintes sha256, copie si besoin et envoie un SIGHUP. À la première copie, le script renomme .pending en .conf puis lance docker compose restart mqtt (VÉRIFIÉ, scripts/mqtt-certs.sh:64-122).
  • Aucun consommateur n'est déployé : pas de CouchDB, pas de pont, pas de dashboard (VÉRIFIÉ, backlog CLAUDE.md:163-173).

Schéma de flux

API / interfaces

  • Points d'entrée réseau : mqtts://mqtt.naonedge.com:8883, wss://mqtt.naonedge.com (443), naonedge-vps-mqtt:1883 en interne (VÉRIFIÉ, specs/instructions/mqtt-broker-vps.md:112-116).
  • HTTP : https://mqtt.naonedge.com sans en-tête Upgrade répond 200 "naonedge mqtt broker", ce qui sert de sonde de santé (VÉRIFIÉ, stack/Caddyfile:92-94).
  • CLI d'exploitation : scripts/mqtt-certs.sh [--force], où --force recopie et relance même si le cert n'a pas changé (VÉRIFIÉ, scripts/mqtt-certs.sh:18-21). Les comptes se créent avec mosquitto_passwd en mode interactif, jamais avec -b (VÉRIFIÉ, README.md:56-57).
  • Fichiers lus par le script : /opt/naonedge-vps/.env (MQTT_DOMAIN) et /var/lib/docker/volumes/naonedge-vps-caddy-data/_data/caddy/certificates/*/<domaine>/<domaine>.{crt,key} (VÉRIFIÉ, scripts/mqtt-certs.sh:25-29,42,49-50).
  • Fichiers écrits par le script : mosquitto/certs/server.crt (644) et server.key (640), uid:gid 1883, ainsi que le renommage de conf.d/8883-tls.conf.pending (VÉRIFIÉ, :77-100).
  • Fichiers montés en lecture seule : mosquitto.conf, conf.d/, passwd, acl, certs/ (VÉRIFIÉ, compose.yml:239-244). Ne sont pas commités : passwd, certs/, conf.d/8883-tls.conf (VÉRIFIÉ, .gitignore:8-11).

MQTT

Comptes et ACL (VÉRIFIÉ, stack/mosquitto/acl:1-10). Aucune règle globale : ce qui n'est pas listé est refusé.

CompteDroitsUsage
iakaframe-publisherwrite iakaframe/#agents (Mac, Windows, VPS)
bridgeread iakaframe/#futur pont MQTT → CouchDB
dashboardread iakaframe/#, read $SYS/broker/#futur dashboard WSS

Schéma de topics : il est réservé mais pas encore implémenté (VÉRIFIÉ, specs/instructions/mqtt-broker-vps.md:173-191).

  • La forme est iakaframe/<projet>/<agent>/<evenement>, avec <evenement> ∈ run/start, run/end, delegation, state, jalon.
  • Le payload est en JSON : { "ts", "project", "agent", "event", "payload" }, avec ts en ISO 8601 UTC.
  • Convention visée : QoS 1, et retain sur state uniquement. Le broker n'impose rien de tout cela (:189-191).
  • Main courante historique : iakaframe/_logs/<royaume>/<agent>/<conv> avec IAKALOG_PREFIX=iakaframe/_logs (VÉRIFIÉ, :193-196).

Émetteurs présents dans ce dépôt, sous global/hooks/ (VÉRIFIÉ) :

  • delegation-guard.mjs:252-277 construit un CONNECT MQTT 3.1.1 avec user/pass (0xC2) puis un PUBLISH 0x30, c'est-à-dire QoS 0 sans retain. Topic : ${IAKALOG_PREFIX||"logs"}/<royaume>/<agent>/<conv>, URL tirée de IAKALOG_BROKER_URL, port 1883 par défaut. Transport node:net (:32,277), donc pas de TLS.
  • plan-courante.mjs:130-145 ouvre une socket TCP puis la ferme sans rien publier (commentaire :141-142 : « Publication broker minimale non implémentée »).

Client de référence : ~/.claude/skills/iakaframe-log-conversation/iakalog.mjs n'accepte que mqtt://, ne publie qu'en QoS 0 et ne sait pas faire de TLS (VÉRIFIÉ par l'instruction, mqtt-broker-vps.md:50-58). Je n'ai pas relu ce fichier, qui est hors du dépôt.

Ergonomie

Le broker n'a aucun écran. Les seules surfaces visibles sont les suivantes :

  • la réponse texte naonedge mqtt broker sur https://mqtt.naonedge.com (VÉRIFIÉ, Caddyfile:93) ;
  • les journaux docker logs naonedge-vps-mqtt (log_dest stdout, mosquitto.conf:12) et la sortie horodatée de mqtt-certs.sh (log(), :39) ;
  • la vue abonné mosquitto_sub -h mqtt.naonedge.com -p 8883 --capath /etc/ssl/certs -t 'iakaframe/#' -v (VÉRIFIÉ, mqtt-broker-vps.md:474).

Pour une annotation, le mieux est un schéma de flux plutôt qu'une capture : trois voies d'entrée (8883, 443 WSS, 1883 interne), puis trois comptes et une ACL.

Points ouverts

  • Écart de nom de variable. Les hooks lisent IAKALOG_BROKER_URL (delegation-guard.mjs:258, plan-courante.mjs:131), alors que l'instruction et les runners posent IAKALOG_MQTT_URL (mqtt-broker-vps.md:418). SUPPOSÉ : les hooks ne joignent pas le broker VPS tel que les runners sont configurés.
  • Hooks sans TLS. Ils passent par node:net sur un port par défaut de 1883, qui n'est pas exposé sur l'hôte. Ils ne peuvent donc pas atteindre :8883 (VÉRIFIÉ pour le transport ; échec SUPPOSÉ).
  • Préfixe par défaut hors ACL. Le préfixe par défaut logs des hooks sort de l'ACL (iakaframe/#), si bien que la publication est refusée si IAKALOG_PREFIX n'est pas posé (VÉRIFIÉ pour le code et l'ACL ; effet SUPPOSÉ).
  • plan-courante.mjs ne publie rien en transport broker (VÉRIFIÉ, :140-145).
  • Divergence dépôt / VPS. Le dépôt livre 8883 en .pending, alors qu'il est actif sur le VPS (VÉRIFIÉ, README.md:13-16). La configuration réelle du VPS n'a pas été relue.
  • CA-12 non fait. Il manque le test depuis le PC Windows et IAKALOG_* sur le PC et iakagent (VÉRIFIÉ, CLAUDE.md:159-160).
  • Durcissements au backlog : websockets_origin, fail2ban, un compte par runner (VÉRIFIÉ, mqtt-broker-vps.md:556-558).
