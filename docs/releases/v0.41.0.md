## Changement observable

- **Étapes 3/4 (IakaCockpit, iakaFrameGUI) couvrent désormais macOS, Linux et Windows.** Seuls
  `win32/arm64`, `linux/arm64` et `darwin/ia32` restent refusés explicitement (CA-15) ; toute clé
  d'installeur absente du manifeste (M6) refuse nommément — jamais une simulation.
- **Sur Linux** : pose l'**AppImage** — copie de l'octet vérifié (signature minisign) + `chmod +x`
  — sous `<apps-dir>/<Nom>.AppImage` (même drapeau `--apps-dir`, même défaut `~/Applications`
  qu'macOS). Aucun `.desktop` écrit (successeur `LANCEUR-DESKTOP-LINUX`). Le lancement réel de
  l'AppImage sur une distribution (avec ou sans FUSE 2) reste un **gate humain**.
- **Sur Windows** : exécute l'installeur `.exe` NSIS `currentUser` en silencieux (`/S`, jamais
  `/R` : pas d'UAC) — **`--apps-dir` n'a aucun effet** (E-4, annoncé explicitement à chaque
  étape). **Jamais le `.msi`** (`perMachine`, UAC obligatoire) : exclu doctrinalement. Avant
  d'écrire, lit le registre de désinstallation (`HKCU\...\Uninstall\<productName>`) : une version
  installée dont `InstallLocation` est indéterminable fait **refuser d'écrire**.
- **Rollback Windows par désinstalleur synchrone** : l'appel porte désormais `/S
  _?=<InstallLocation>` (obligatoire — sans lui, NSIS se copie dans `%TEMP%` et rend la main
  avant la fin réelle, doc NSIS officielle *Command Line Parameters*) ; un code `0` ne suffit
  plus, la disparition de la sous-clé de registre est **confirmée** par relecture (bornée à 10
  tentatives espacées) avant de déclarer `defait:true` — sinon `ok:false`, désinstallation NON
  confirmée nommée comme telle. Le résidu de nettoyage (`uninstall.exe`/dossier non
  auto-supprimés par `_?=`, doc NSIS *Uninstall Section*) fait l'objet d'un nettoyage
  best-effort ; un échec de ce nettoyage est **énoncé** (« résidu non nettoyé »), jamais masqué
  ni bloquant pour un verdict de désinstallation déjà confirmée.
- **Refus explicite conservé** pour `win32/arm64` et pour toute clé de manifeste absente — jamais
  un succès simulé.

## Preuve sur runner réel

Un run réel du banc CI (`banc-etapes-3-4.yml`, `workflow_dispatch`, run `33997947501`,
2026-09-06) a mesuré les deux plateformes dans la même exécution matricielle
(`ubuntu-latest`/`windows-latest`) : **Linux 100 % vert** ; **Windows vert sauf les deux lignes
de rollback** (scénarios A IakaCockpit et iakaFrameGUI), qui rendaient `ok:true, defait:true,
codeUninstall=0` alors que la sous-clé de registre était **encore présente** juste après le
retour de `uninstall.exe /S` — c'est cette mesure réelle qui a motivé le correctif `_?=`
ci-dessus (lot `610c2bd`). Un second run, post-correctif, reste dû pour prouver que le rollback
Windows passe désormais au vert sur runner réel — geste du décideur (`gh workflow run
banc-etapes-3-4.yml --repo iakasju/iakaframe -f os=les-deux -f rollback=true`).
