iakaframe face au dev multi-agents

Où se situe iakaframe dans la famille des méthodes et frameworks de développement piloté par plusieurs agents d'IA ? Ce qu'elle partage, ce qui la distingue, et ce qu'elle pourrait emprunter.

v0.2.0 · 2026-07-05 · faits vérifiés au web + lectures comparatives
Comprendre

Positionnement : deux pôles, une famille

Depuis 2023, une famille d'approches fait collaborer plusieurs agents d'IA pour produire du logiciel. Elles se répartissent sur un axe : d'un côté la discipline « humain-partenaire » (le workflow encadre, l'humain décide), de l'autre l'essaim autonome (on optimise le débit et l'autonomie). iakaframe se range clairement au premier pôle.

Convention de lecture : les faits sont sourcés par une URL (voir chaque carte + l'onglet Sources). Les lectures comparatives — nos rapprochements, nos jugements de proximité — sont signalées par un encart « Lecture (la nôtre) » et n'engagent que nous.

Pôle A · discipline humain-partenaire

Le workflow produit la qualité ; l'humain valide à des jalons. Spec avant code, revue humaine.

  • iakaframe — rôles fermés, jalons humains, self-hosted souverain
  • BMAD-METHOD — « partnership over automation », agile story-driven
  • GPT-Pilot — l'humain relit chaque tâche (comme une revue de PR)
Pôle B · essaim autonome / débit

On maximise l'autonomie et le débit ; l'humain intervient peu. Orchestration massive, benchmarks.

  • Ruflo (ex-Claude-Flow) — « hive-mind », quasi-autonome
  • MetaGPT — « first AI software company », SOP autonome
  • ChatDev — entreprise logicielle virtuelle (recherche)

Lecture (la nôtre) — la ligne de partage

Ce qui sépare les deux pôles n'est pas la technique (tous font du multi-agents) mais la place de l'humain et la finalité : le pôle A optimise le contrôle (traçabilité, revue, périmètres étanches) ; le pôle B optimise le débit autonome (parallélisme, benchmarks, autonomie). iakaframe et BMAD sont des disciplines ; Ruflo et MetaGPT sont d'abord des moteurs.

iakaframe référence

  • Nature — méthode / discipline (protocole de rôles, gestes, jalons).
  • Rôles — coordination de portefeuille & de projet, cadreur-architecte, développeur-devops, vérificateur qualité, studio design, rédactrice, squad prod ; décideur = l'utilisateur.
  • Phases — 3 phases (cadrage → réalisation → staging) + squad prod séparé.
  • Humain — jalons humains (validation d'instruction, feu vert prod) ; anti-auto-validation.
  • Runners — Claude Code, Codex, Ollama, Open WebUI, AnythingLLM (kits) ; équipe hétérogène possible.

Réf. interne : methode-de-travail.md · doc chapeau iakaframe-chapeau.html.

BMAD-METHOD jumeau philosophique

  • Nature — méthode / discipline, 100 % open source (~50,1k★ au relevé du 2026-07-05).
  • Personas — 12+ nommés : Analyste, PM, Architecte, Product Owner, Scrum Master, Développeur, QA, UX, Rédacteur technique (system prompts : persona + menu + mémoire).
  • Phases — Analysis → Planning → Solutioning → Implementation (agile, story-driven, sprints).
  • Spec — PRD 1 page + user stories à critères d'acceptation.
  • Humain — « partnership over automation », ne remplace pas le jugement ; checkpoints.
  • Runners — Claude Code (recommandé), Cursor, Codex CLI + web bundles (Google Gemini Gems, ChatGPT Custom GPTs).
  • Install — npx bmad-method install (Node 20.12+ / Python 3.10+, mode CI/CD).
  • Innovations — scale-adaptive planning, 34+ workflows, modules d'extension (BMad Builder, Test Architect TEA, Game Dev Studio, Creative Suite), « Party Mode », skill bmad-help.

Sources : github · docs · augmentcode · diegorodrigo

Ruflo (ex-Claude-Flow) cousin technique

  • Nature — moteur d'orchestration « hive-mind ».
  • Personas — une queen agent décompose ; 100+ agents spécialisés en parallèle ; consensus queen-led (Raft / Byzantine / Gossip) ; topologies hiérarchique / mesh / adaptive.
  • Méthode — SPARC embarquée : Specification → Pseudocode → Architecture → Refinement → Completion — « méthodologie en 5 phases à quality gates ».
  • Mémoire — AgentDB indexée HNSW + ReasoningBank + SONA ; RAG natif.
  • Humain — quasi-autonome (hooks en arrière-plan, « tourne sans commandes explicites »).
  • Perf — 84,8 % SWE-bench (benchmark auto-déclaré : Ruflo orchestrant Claude Sonnet 4.5, sans entraînement supplémentaire) ; ~75 % d'économies API ; 4-6+ outils simultanés.
  • Runners — multi-runner : natif Claude Code / Codex / Hermes « and many more » + ruvLLM (modèle local) + SONA.
  • Adoption — ~63,1k★, ~7 130 commits (repo ruvnet/ruflo, au relevé du 2026-07-05 ; en forte croissance — sources antérieures : 31k–58,9k selon la date). Réécrit en Rust, renommé (janv. 2026).

Sources : github ruvnet/ruflo · wiki SWE-bench · pasqualepillitteri.it

MetaGPT

  • Nature — framework « first AI software company » (~67k★ au relevé du 2026-07-05).
  • Rôles — 5 typés : Product Manager, Architect, Project Manager, Engineer, QA Engineer.
  • Idée clé — « Code = SOP(Team) » ; le PM produit un PRD (User Stories + Requirement Pool) ; communication par artefacts / handoffs structurés, pas par chat.
  • Humain — surtout autonome. Papier ICLR.

Sources : github · arXiv 2308.00352v6 · IBM

  • Rôles — CEO / CTO / programmeur / relecteur / testeur.

  • Communication — par dialogue entre rôles.

GPT-Pilot / Pythagora pôle humain

  • Nature — outil « the first real AI developer ».
  • Rôles — Specification Writer / Architect / Tech Lead / Developer / Debugger.

CrewAI

  • Nature — framework d'agents.
  • Agents — définis par « Role – Goal – Backstory ».
  • Orchestration — « crews » à process typés (séquentiel / hiérarchique).

Source : github

Deux voisins méritent une comparaison serrée : BMAD (jumeau philosophique) et Ruflo (cousin technique, opposé philosophiquement).

Lecture (la nôtre) : Ruflo optimise le débit qu'une IA peut produire seule ; iakaframe optimise le contrôle qu'un humain garde sur ce qui est produit. Même boîte à outils, thèse inverse : l'un veut que l'IA en fasse le plus sans nous, l'autre veut qu'elle en fasse le plus sous notre décision. À noter (fait) : le multi-runner n'est pas ce qui les sépare — Ruflo aussi est multi-runner (Claude/Codex/Hermes) ; la vraie ligne de partage reste la place de l'humain et la souveraineté self-hosted.

Comprendre

La signature d'iakaframe

Ce qu'aucun autre du corpus ne réunit au même endroit — la combinaison qui fait l'identité de la méthode.

Mise au point (fait vérifié) : l'agnosticisme / multi-runner n'est pas un différenciateur d'iakaframe — BMAD (Claude/Cursor/Codex + bundles web) et Ruflo (Claude Code / Codex / Hermes « and many more ») sont aussi multi-runner. Ce qui reste vraiment propre à iakaframe, ce sont les quatre traits ci-dessous.

Le canal d'identité (badges verbatim)

Chaque prise de parole porte un badge <pastille> [ROYAUME][Rôle] ; la position de la pastille marque ouverture/clôture ; une restitution en relais cite l'émetteur verbatim, sans ventriloquie. On sait toujours qui a écrit quoi. Peu d'approches du corpus formalisent l'attribution à ce point.

La coordination de portefeuille

Un niveau au-dessus des projets oriente et répartit entre eux, puis passe la main à la coordination de projet. La plupart des autres approches s'arrêtent au périmètre d'un projet.

Le self-hosted souverain

Forge Forgejo, modèles Ollama, Open WebUI, Docker par projet (réseau/volumes/ports isolés). La souveraineté des données est un parti pris, pas une option.

Le décideur humain aux jalons

Deux jalons non automatisables (validation d'instruction, feu vert prod) et un gate qualité indépendant : celui qui code ne se valide jamais lui-même.

Lecture (la nôtre) : pris isolément, chacun de ces traits existe ailleurs. Leur réunion — identité tracée + portefeuille + souveraineté + contrôle humain — est ce qui distingue iakaframe dans la famille.

Emprunts possibles (backlog)

Ce que la veille suggère d'étudier pour iakaframe — sans renier sa signature (contrôle humain, souveraineté). À arbitrer par le décideur.

EmpruntOrigineCe que ça apporteraitVigilance
Scale-adaptive planning BMAD Ajuster la profondeur du cadrage/gate à la complexité réelle du changement. Déjà amorcé (profondeur du gate) — formaliser sans alourdir.
Galerie d'outils MCP Ruflo Un catalogue d'outils MCP réutilisables, brochables par rôle. Garder le périmètre étanche par rôle (pas d'outil tout-puissant).
Mémoire distribuée / fédérée Ruflo Partager une mémoire entre instances/projets d'un même portefeuille. Ne pas casser l'étanchéité inter-projets ; rester self-hosted.
Culture benchmark (SWE-bench) Ruflo Mesurer objectivement la méthode sur des tâches standardisées. Un score ne remplace pas le jugement humain (notre thèse).
Bundles web (runners non-CLI) BMAD Porter les rôles vers des runners sans CLI (Gems, Custom GPTs). Cohérent avec l'agnosticisme des kits ; préserver le rituel d'identité.

Lecture (la nôtre) : aucun de ces emprunts n'entame la signature d'iakaframe s'il est adopté en gardant l'humain aux jalons et la souveraineté self-hosted. On emprunte des gestes, pas une philosophie.
