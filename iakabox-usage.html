Aperçu

Qu'est-ce qu'iakabox ?

Un serveur unique (bigserver, Proxmox VE 9, hôte 192.168.2.20) qui fait tourner 5 machines virtuelles, chacune dédiée à un rôle. L'ensemble est déployé en Infrastructure-as-Code (Ansible) et remplace une pile de services cloud par des équivalents auto-hébergés sur le LAN.

L'essentiel

Git avec Forgejo

Forgejo (fork léger de Gitea) est le serveur git privé d'iakabox. Tous les projets y vivent : robotimmo, iakabox, et désormais les projets démarrés avec la méthode iakaframe.

ÉlémentValeur
Web UIhttp://192.168.2.11:3001
Comptesjupin
Pattern de remotehttp://192.168.2.11:3001/sjupin/<repo>.git
AuthHTTP + token (SSH inutilisable, voir plus bas)
Dépôts privésoui par défaut (LAN protégé)

SSH ne marche pas. Le port 22 de 192.168.2.11 répond avec le sshd système de la VM, pas le serveur SSH de Forgejo : les clés du compte Forgejo n'y sont pas honorées (Permission denied (publickey)). Toujours utiliser HTTP + token. Ne pas s'acharner sur SSH.

1. Générer un token

Dans Forgejo : Paramètres → Applications → Générer un nouveau token. Scopes nécessaires :

  • write:repository — pour push/pull
  • write:user — en plus, pour créer un dépôt via l'API

Garder le token côté client (dans .git/config local ou une variable d'environnement). Ne jamais le committer.

2. Cloner / configurer un dépôt existant

# Clone avec token intégré dans l'URL (le plus simple sur le LAN)
git clone http://sjupin:$TOKEN@192.168.2.11:3001/sjupin/robotimmo.git

# Ou : ajouter/rebrancher le remote sur un repo local
git remote add origin http://sjupin:$TOKEN@192.168.2.11:3001/sjupin/<repo>.git
git push -u origin main

Le token dans l'URL = pas de re-saisie. Une fois origin configuré avec le token, git push fonctionne sans redemander d'identifiant. Le token vit dans .git/config (non committé).

3. Créer un nouveau dépôt (API)

# T = token avec scope write:user. Description en ASCII uniquement !
curl -s -X POST \
  -H "Authorization: token $T" \
  -H "Content-Type: application/json" \
  -d '{"name":"mon-projet","private":true,"auto_init":false,"description":"ASCII only"}' \
  http://192.168.2.11:3001/api/v1/user/repos

Description ASCII obligatoire. Un tiret cadratin « — » ou tout caractère non-ASCII casse l'encodage et renvoie HTTP 422 « invalid UTF-8 ». Rester en ASCII pur dans le champ description.

4. Roter le token

git remote set-url origin http://sjupin:NOUVEAU_TOKEN@192.168.2.11:3001/sjupin/<repo>.git
git push

Avec iakaframe, ces étapes sont automatisées : iakaframe-onboard.ps1 crée le dépôt Forgejo, branche le remote (token lu depuis $env:FORGEJO_TOKEN) et fait le premier push. Voir le guide méthode.

Stockage partagé

Le partage work (SMB, 8 To)

L'hôte Proxmox (192.168.2.20) expose un partage Samba sur le HDD 8 To, pour le stockage temporaire et les sauvegardes.

ÉlémentValeur
Chemin Windows\\192.168.2.20\work
Chemin serveur/hdd/work (quota 4 To partagé)
Comptes Sambaiaka, sjupin (groupe iaka, écriture)
SSH hôtessh root@192.168.2.20 (clé ~/.ssh/iakabox_key, Host bigserver)

Ne pas lancer une stack Docker depuis le montage SMB (bind-mounts cassés, surtout sur macOS). Cloner et exécuter en local ; le partage sert au stockage et aux backups, pas à l'exécution.

Sauvegardes utiles présentes sur work/ : claude-backup/ (conversations Claude, 10 projets), sources-backup/ (sources non-git), ssh-backup/ (clés dont iakabox_key).

Dépannage

Problèmes courants

« Permission denied (publickey) » au git push

Vous utilisez SSH. Bascule sur HTTP + token : git remote set-url origin http://sjupin:$TOKEN@192.168.2.11:3001/sjupin/<repo>.git

Création de dépôt → HTTP 422 « invalid UTF-8 »

La description contient un caractère non-ASCII (souvent un « — »). Mettre une description en ASCII pur.

Ollama : erreur CUDA

Driver NVIDIA trop ancien sur VM3. Passer en driver 580+.

Un service ne répond pas par son nom .bigserver.local

Pas de DNS local : utiliser l'IP:port directe, ou ajouter l'entrée dans le hosts du poste (→ 192.168.2.10).

Inspecter / relancer un conteneur

Logs en temps réel via Dozzle (192.168.2.13:8097) ou Portainer (192.168.2.11:9000). En SSH sur la VM : docker ps, docker logs <c>, docker compose restart <svc>.
